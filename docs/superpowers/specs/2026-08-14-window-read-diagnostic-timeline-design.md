# 主页读取诊断时间线设计

## 目标

“窗口测试”弹窗按照真实执行顺序展示主页定位、页面读取、候选判定、滚动、页面稳定检测和文章解析结果。被丢弃或跳过的候选必须展示标题片段与具体原因，便于定位漏读和误读。

## 数据边界

- `article_card_reader.py` 只负责生成文章候选和候选判定结果，不直接组织前端文案。
- `home_article_cursor.py` 负责把页面读取、滚动和稳定检测转换成结构化诊断事件；默认没有监听器，不影响主流程。
- `window_click_flow_diagnostic_service.py` 保存有序事件流，将文章结果、日期筛选跳过和窗口事件合并为同一条时间线。
- `SettingsPage.vue` 按事件类型渲染摘要、操作、丢弃候选和文章详情，不推断业务结果。

## 时间线顺序

1. 定位公众号主页窗口。
2. 读取当前屏并记录文本范围数、有效文章数、丢弃候选数和耗时。
3. 展示本次读取中的丢弃候选及原因。
4. 依次展示被接收的文章详情。
5. 当前屏候选处理完成后记录滚动方向、步数和发送结果。
6. 页面变化检测结束后记录轮询次数、等待时间和稳定结果。
7. 读取下一屏并重复上述过程，直到达到任务数量、日期边界、没有更多文章或用户停止。

## 候选判定

- 继承上一屏日期但没有日期节点或前一阅读指标作为边界：丢弃标题残片。
- 阅读指标没有完整可点击矩形：丢弃并记录指标文本。
- 标题与阅读指标共用同一矩形：视为滚动过渡帧并丢弃。
- 有明确日期或前一阅读指标边界、阅读指标完整时，即使个别标题行没有矩形，也保留 UIA 返回的完整标题文本，避免漏读。
- 日期筛选跳过或到达边界时，展示标题、日期和判定原因。

## 展示规则

- 顶部继续显示当前动作；正文保存不可覆盖的历史时间线。
- 高频轮询不逐次输出相同快照，只在内容变化或阶段结束时追加记录。
- 操作记录使用紧凑行，文章结果保留当前详细字段，丢弃记录使用警告状态。
- 实时追加时仅在用户位于列表底部附近自动跟随；用户向上查看历史记录后不强制拉回底部。

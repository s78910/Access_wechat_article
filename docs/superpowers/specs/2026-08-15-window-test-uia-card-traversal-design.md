# 窗口测试 UIA 卡片遍历设计

## 目标

“窗口测试”只使用公众号主页 UIA 控件树中的“日期组 -> 文章卡片”关系遍历文章。文章边界不再依赖“阅读 xx”，滚动前后使用“日期原文 + 完整标题原文”衔接，并记录文章卡片在当前内容可视区内的实际矩形和中心点。

## 数据边界

- UIA 快照读取器一次遍历 Document 控件树，输出日期组、组内文章卡片、完整标题、原始卡片矩形、可视矩形和中心点。
- 日期组的直接子 `GroupControl` 是单篇文章边界；“阅读/点赞”只作为可选字段，不参与卡片存在性判断。
- 窗口测试服务负责激活主页、调用快照读取器、应用数量与日期过滤、控制滚动、衔接上一屏末尾卡片和触发回弹。
- 主流程的 `HomeArticleCursor`、文章点击、MITM、标签关闭不参与窗口测试。

## 可视区规则

- 主页内容可视区为 Document 与主页窗口的交集，并从 UIA 分类导航栏下沿开始。
- `visible_rect = card_rect ∩ content_viewport`。
- `visible_rect` 高度小于 10 像素时忽略；否则保留，包括原始卡片坐标在视口上方或下方的部分可见卡片。
- 诊断点击坐标为 `visible_rect` 中心点，不执行真实点击。

## 滚动衔接

1. 首次快照从可视区第一篇开始记录。
2. 保存本轮最后一篇的“日期原文 + 完整标题原文”。
3. 向下滚动后，在滚动观察阶段低频轮询 UIA 快照。
4. 在完整已加载卡片序列中找到上一轮标记，只追加其后且当前可见的文章。
5. 配置时间内没有新文章时执行回弹；回弹次数耗尽后结束。
6. UIA 只在首次读取和滚动后的观察阶段访问，筛选、排序和记录均使用不可变快照。

## 展示与记录

- 弹窗只展示成功识别的文章：日期、标准日期、完整标题、完整卡片坐标、可视卡片坐标、可视高度和中心点。
- 窗口激活、快照、滚动、轮询、游标衔接、回弹及终止原因写入 `data/tmp/window-click-flow/` 诊断文件。
- 保留现有任务数量、日期筛选、实时弹窗、立即停止和异步 API。
